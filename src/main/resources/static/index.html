bank-core ― 勘定系コアバンキング

口座開設・入出金・行内振込・取消から、日次締め（利息・口座振替・融資の約定返済・延滞管理・有価証券・信託・ 加盟店精算・AML 監視）・照合・承認までを、この 1 画面と REST API で再現する教育用サンプルです。 実在の顧客口座や決済網には接続していません。

Java 21 · Spring Boot 3.5 PostgreSQL 16 · Flyway 複式簿記 冪等キー Transactional Outbox Testcontainers JP1 連携
Architecture 1 取引 = 1 DB トランザクション

冪等キーの予約 → 口座を ID 昇順でロック → 業務ルールの検証 → 残高更新・複式仕訳・Outbox を同じトランザクションで 記帳 → コミット。仕訳は貸借一致を DB トリガーが検証し、記帳後は変更・削除できません。

Recommended 5 分で一通り試す
  • 「口座開設」で 2 口座（例：山田 太郎・佐藤 花子）を作る
  • 「現金 入金 / 出金」で 1 口座目に 100,000 円を入金する
  • 「行内振込」で 30,000 円を振り込み、同じキーのままもう一度押す → 二重にならないことを確認
  • 口座一覧の「明細」→ 振込の行の「取消」で反対仕訳が入ることを確認
  • 「日次締めを実行」→「承認」（実行者と別の人）で業務日付が翌日に進む
  • 「照合を実行」→ ヘッダーの照合バッジが 一致 になる

やってよいこと

  • 資金が動く操作は必ず Idempotency-Key を付け、タイムアウト時は同じキーで再送する
  • 締めが途中で失敗したら、原因を取り除いてそのまま再実行する（続きから処理・二重計上なし）
  • 照合が不一致なら、修復を記録してから再実行する（日付は進まない）

やらないこと

  • DB の残高や仕訳を SQL で直接書き換えない（照合で検出され、締めが止まる）
  • 実在の口座番号・個人情報を入力しない（認証・マスキングは未実装）
  • 本番の決済網（全銀・SWIFT・カードブランド）につなぐ用途に使わない
Troubleshoot うまくいかないとき
  • ヘッダーが「API 接続不可」：docker compose ps で app と db が起動しているか確認
  • HTTP 400：入力の誤り（金額が 0 以下・キーの文字種・必須項目の不足）
  • HTTP 409：同じキーで内容を変えた／取消済み・承認済みなど状態が合わない
  • HTTP 422：業務ルールで拒否（残高不足・凍結口座・通貨不一致）。取引は REJECTED として記録される
  • HTTP 503：ロック待ちが続いた。同じキーで再送すれば安全

↓ 起動から運用までの手順

  1. 1. 起動と状態確認

    Docker Desktop を起動し、bank-core のフォルダーで起動します。

    • docker compose up -d --build（初回はイメージのビルドに数分）
    • ブラウザで http://localhost:18080 を開く
    • ヘッダー右：業務日付 / API 稼働中 / 照合の結果を確認
    • DB はホストの localhost:15432（ユーザー・パスワード・DB 名はすべて bankcore）
  2. 2. 口座開設

    名義・通貨・当座貸越枠を入れて「開設」を押します。

    • 通貨は ISO コード（JPY / USD など）。外貨口座は両替・海外送金で使う
    • 口座番号は 7 桁で自動採番。残高 0・状態 ACTIVE で作られる
    • 当座貸越枠を設定すると、残高がマイナスでもその額まで出金できる
  3. 3. 現金の入金・出金

    口座と金額を選び、Idempotency-Key を確認して「入金」または「出金」を押します。

    • キーは画面を開いたときに自動で入る。別の取引にするときは「新しいキー」
    • 成功は HTTP 201。残高不足・凍結口座は HTTP 422（拒否も取引として記録）
    • 仕訳：入金は 借方 現金 / 貸方 預金、出金はその逆
  4. 4. 行内振込と冪等性

    振込元・振込先・金額（メモは任意）を入れて「振込」を押します。

    • 同じキーのまま再度押す → 結果は同じで Idempotent-Replayed: true（二重に振り込まれない）
    • 同じキーで金額を変える → HTTP 409（別の依頼にキーを使い回した誤り）
    • 振込元と振込先は同じ口座にできない。通貨が違う口座へは振り込めない
  5. 5. 明細と取消（反対仕訳）

    口座一覧の「明細」で、その口座の仕訳（業務日付・摘要・入出金）を表示します。

    • 「取消」は元の仕訳を変えず、貸借を入れ替えた仕訳を新しい取引として記帳する
    • 同じ取引の 2 回目の取消・取消取引の取消は HTTP 409
    • 取消で相手口座の残高が足りないときは HTTP 422（入金後に再度取消できる）
  6. 6. 口座の凍結・解除

    口座一覧の「凍結」「凍結解除」で状態を切り替えます。

    • 凍結中の口座への入出金・振込は HTTP 422（TARGET / SOURCE_ACCOUNT_NOT_ACTIVE）
    • 解約（CLOSED）は残高 0 のときだけ API から可能で、元に戻せない
  7. 7. 日次締め（実行 → 承認）

    実行者と承認者を入れて「日次締めを実行」を押します。10 のステップを順に処理します。

    • 利息計上 → 口座振替 → 融資の自動引落し → 延滞判定と引当 → 有価証券の利金・償還 → 時価評価 → 信託の満期払出し → 加盟店精算 → AML 監視 → 照合
    • 照合に合格すると AWAITING_APPROVAL。実行者とは別の人が「承認」すると業務日付が翌日へ
    • 「差戻し」は理由が必要。状態は REJECTED になり、修復してから再実行する
    • 「状態を表示」で各ステップの件数・試行回数と監査ログ（誰がいつ何をしたか）を確認
    • 途中で失敗しても再実行で続きから処理。各記帳は業務日付付きの冪等キーで二重計上しない
  8. 8. 照合（リコンサイル）

    「照合を実行」で帳簿の整合性を確かめます（読み取りのみ）。

    • 仕訳ごとの貸借一致・口座残高と仕訳の一致・融資残高と貸付元帳の一致
    • 仮受金などの経過勘定と明細の一致、試算表の貸借一致
    • 不一致の項目は結果の JSON に口座・融資ごとに表示される
  9. 9. 画面にない業務（API で操作）

    融資・為替・証券・投信と信託・カード・CRM・AML・リスク管理は API から操作します（PowerShell の例）。

    • 融資：POST /api/loan-applications → 担保・保証 → /screening → /decision（受付者以外）→ /disbursement
    • 為替：/api/book-transfers（振替）/api/domestic-remittances（他行・全銀） /api/fx-exchanges（両替）/api/foreign-remittances（海外送金・制裁照合）
    • 証券・投信・信託：/api/securities/trades /api/fund-orders/subscriptions /api/money-trusts
    • カード：/api/cards → /api/card-authorizations → /capture、電子マネーは /api/wallets
    • CRM・AML・リスク：/api/customers /api/aml/alerts /api/risk/dashboard
    • 例：Invoke-RestMethod http://localhost:18080/api/risk/dashboard
  10. 10. ジョブスケジューラ（JP1）連携

    締めをジョブとして起動し、終了コードで結果を判定します。

    • scripts\jp1\run-job.ps1 -Job daily-closing（Linux は run-job.sh）
    • 終了コード：0 正常 / 1 承認待ち / 4 照合不一致・差戻し（要修復）/ 8 異常終了（再実行で再開）/ 12 定義誤り
    • closing-status ジョブで承認待ちを待ち合わせ、reconciliation で照合だけ実行できる
  11. 11. テストとデバッグ

    テストはすべて Testcontainers の実 PostgreSQL に対して実行します（Docker Desktop が必要）。

    • .\mvnw.cmd verify または .\gradlew.bat test（342 件）
    • VS Code で bank-core を開き、テストメソッドの行番号の横の ▷ をクリック → そのメソッドだけデバッグ実行
    • F10 ステップオーバー / F11 ステップイン / Shift+F11 ステップアウト / F5 続行
    • 性能計測：.\mvnw.cmd test "-Dtest=OperationsBenchmarkTest" "-Dbench=true" "-Dsurefire.failIfNoSpecifiedTests=false"
  12. 12. 環境・運用メモ

    設定は環境変数で変えられます（docker-compose.yml / application.yml）。

    • CLOSING_APPROVAL_REQUIRED：既定 true（承認が必要）。false で照合合格時に自動で日付を進める
    • 締めの並行数 bank.closing.parallelism：既定 8（接続プール 20 未満）
    • ヘルスチェック：GET /actuator/health
    • Docker のビルドで失敗するときは COMPOSE_BAKE=false と DOCKER_CONTEXT=desktop-linux を付ける
